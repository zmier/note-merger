# CriticMarkup 可视化功能 PRD

## 1. 背景

当前团队已经形成了一套明确的 CriticMarkup 批注规范，用于论文审读、返修建议和段落级问题标注。

但 Obsidian 原生并不会将 CriticMarkup 渲染为可视化标记，导致用户在阅读视图或实时预览中看到的仍是原始语法，例如：

- `{++新增内容++}`
- `{--删除内容--}`
- `{~~原文~>改文~~}`
- `{==高亮内容==}`
- `{>>批注内容<<}`

这会带来三个直接问题：

1. 审稿时视觉负担大，难以快速区分“新增 / 删除 / 替换 / 评论”。
2. 长篇文稿中批注密度一高，原始符号会破坏阅读连贯性。
3. 现有批注体系已经成熟，但在 Obsidian 内没有得到对应的可视化承接。

## 2. 目标

在 `note-merger` 插件中新增 CriticMarkup 可视化能力，使 Obsidian 在展示带有 CriticMarkup 的文稿时，能够以统一、克制、学术友好的方式渲染不同类型的批注。

## 3. 用户价值

- 审稿时能快速扫视修改类型
- 修改意见与正文之间的关系更直观
- 保留纯文本可移植性，同时获得接近专业审稿工具的阅读体验
- 为后续扩展“接受修改 / 过滤视图 / 导出审稿稿”打基础

## 4. 适用范围

本期优先支持：

- 阅读视图
- Live Preview
- 普通 Markdown 段落、列表、标题、引用块中的 CriticMarkup

本期暂不处理：

- 复杂嵌套 CriticMarkup
- 代码块、行内代码中的 CriticMarkup
- “接受/拒绝修改”交互按钮
- 导出 PDF / HTML 时的专用样式包

## 5. 核心语法支持

### 5.1 Addition

```text
{++插入的文字++}
```

渲染目标：

- 柔和绿色底色
- 轻边框
- 正常文本，不加删除线

### 5.2 Deletion

```text
{--要删除的文字--}
```

渲染目标：

- 柔和红色底色
- 删除线
- 保留原文可见，便于审稿

### 5.3 Substitution

```text
{~~原文~>建议改为~~}
```

渲染目标：

- 旧文本显示为删除态
- 新文本显示为新增态
- 中间用箭头分隔

### 5.4 Highlight

```text
{==被高亮的文字==}
```

渲染目标：

- 柔和黄色高亮
- 不改变原文含义，仅突出关注区域

### 5.5 Comment

```text
{>>批注内容<<}
```

渲染目标：

- 使用独立的批注胶囊样式
- 颜色与正文修改类区分开
- 保持简洁，适合密集阅读

## 6. 视觉风格

本期采用“学术马卡龙 + 语义色”的方案，视觉逻辑参考 Ant Design / Material 的语义色体系，但整体饱和度更低，避免长时间审稿时刺眼。

推荐语义：

- 新增：低饱和绿色
- 删除：低饱和红色
- 替换：红绿并置
- 高亮：低饱和琥珀黄
- 批注：低饱和紫色

设计要求：

- 在浅色主题与深色主题下都可读
- 边框与底色要比纯警示色更柔和
- 不做过度动画，不做花哨阴影
- 第一优先级是可读性，第二优先级是美观

## 7. 交互要求

### 阅读视图

- 直接将原始 CriticMarkup 渲染为可视化标记
- 保留文本流，不破坏段落结构

### Live Preview

- 当光标不在该标记上时，显示为可视化样式
- 当用户点击某个可视化标记时，恢复该段原始语法，便于继续编辑

## 8. 验收标准

满足以下条件可视为上线：

1. 五种基础 CriticMarkup 都能被识别并渲染。
2. 阅读视图中不再显示原始语法符号。
3. Live Preview 中可视化标记可点击回到原始文本进行编辑。
4. 代码块与行内代码不被错误处理。
5. 替换语法能明确区分“原文”与“建议改文”。
6. 样式在浅色主题下清晰、柔和、可区分。

## 9. 后续迭代建议

- 增加主题预设：Academic Pastel / AntD / Material
- 增加“只显示评论”“隐藏删除”“只看净稿”等过滤模式
- 增加命令：接受当前文档全部修改
- 增加导出时的审稿样式兼容
